# Dedicated weapon assembly interface

武器装配采用专用装配界面，而不是在世界坐标中直接放置柄部。玩家蹲下并以副手持木棍、主手持武器零件右键后，客户端显示正面朝下的放大零件预览；玩家选择零件下方与轮廓相邻的像素并确认，服务端再验证组合条件、消耗材料并生成完整武器。这样可以精确表达单像素连接规则，并为后续柄部或其他装配件保留可扩展的交互边界。

本阶段的完整武器只承载来源图案、填充材料和连接点，并提供组合后的视觉模型；攻击、耐久和具体武器类型留待后续规则定义。

进入预览不改变库存；无论玩家处于创造、生存还是冒险模式，只有服务端接受有效连接点后才原子地消耗一个武器零件和一根木棍。取消、无效选择或校验失败不会产生部分消耗。

连接点是铸件轮廓正下方的单个空像素，只接受四方向相邻关系，不接受对角线相邻。

装配预览和产物使用统一的标准正面朝下朝向，不携带武器零件来源模具的世界 `FACING`，从而保证同一图案的组合结果一致。

Demo 只接受原版 `minecraft:stick` 作为柄部输入，但产物应保存柄部材料身份，以便后续增加其他柄部材料。

木棍在预览和产物中使用像素化柄部几何：宽度与厚度均为 1 像素、从连接点向下延伸 10 像素，并与连接像素对齐；不直接复用原版木棍图标。

正面朝下只属于装配界面的操作视图。物品栏、第一/第三人称手持、掉落物和展示框均使用标准物品变换，保持柄部朝下；这些展示同样不继承来源模具的 `FACING`。

完整武器最大堆叠数为 1。成功组合后按主手槽、玩家库存、脚下安全掉落的顺序安置产物，避免因库存空间不足而丢失。

装配会话由服务端维护，客户端只提交连接点。会话有效期为 1200 tick（约 1 分钟）；玩家移动不会使会话失效，但物品被替换、界面关闭、断线或服务端校验失败会结束会话，且不会消耗物品。

潜行只用于触发装配会话；界面打开后松开潜行不会取消会话。

装配不按轮廓分类：任意非空武器零件都可操作，所有铸件像素正下方的空像素均可作为连接点。

若铸件不存在任何合法连接点，服务端拒绝创建会话并返回提示，不打开无效预览，也不消耗输入物品。

预览按铸件与柄部的完整边界进行自动整数缩放，尽可能放大但始终保持所有连接点和柄部可见，避免像素插值模糊。

装配预览由服务端会话数据驱动：服务端发送图案、材料、会话 ID 和合法连接点，客户端只渲染并提交选择；最终物品通过普通库存同步传播给其他玩家。

柄部顶部无缝贴合铸件底部；连接点决定合法性，1 像素宽的柄部与连接像素对齐，并随所选连接点整体移动。

输入仍是原版 `minecraft:stick`，但组合模型的柄部视觉参考原版武器和工具的木柄：棕色木质并带有相近的明暗层次，而不是直接使用木棍物品图标。

完整武器使用统一名称，Tooltip 只显示来源填充材料，不把任意轮廓命名为具体武器类型，也不暴露内部像素坐标。

装配界面是多人游戏中的非暂停界面；世界继续运行，玩家死亡、断线或输入物品变化会结束会话且不消耗输入。

当前阶段装配不可逆；完整武器没有拆解右键行为、拆解配方或还原路径。

满足装配条件时，蹲下右键方块或空气都优先触发装配并取消普通右键；条件不满足时保留原版交互。

装配网络消息加入现有 TRMS protocol v1，不升级协议版本；开始、确认和取消均复用现有 v1 通道，最终物品仍通过库存同步。

创造、生存和冒险模式均可装配并在成功时消耗输入；旁观模式不能创建或确认装配会话。
